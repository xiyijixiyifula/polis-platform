## 📐 编码规范
- Rust 代码遵循社区惯用风格（`cargo fmt`）
- 前端使用 TypeScript + Tailwind CSS + `dark:` 变体适配暗黑模式
- 所有 API 返回统一格式：`{ code: int, data?: any, message: string }`
- 关键逻辑必须有错误处理，不能 unwrap()
- 新增功能必须同时更新前端页面
- 网关代理函数使用 `path_and_query()` 而非 `path()` 以保留查询参数
- 公共路由放 `public` Router，需认证的路由放 `auth` Router
- 空间内路径通过 `parse_content_path` 统一解析路由

## 🏛️ 权限架构模型（核心设计理念）

### OS → Disk → Folder → File 映射

```
登录用户 (@xxx)     → OS 系统用户
社区 (Space)         → 磁盘分区 (Disk)
模块 (Module)        → 文件夹 (Folder)
内容 (Post/File/…)   → 文件 (File)
```

### 核心原则（所有模块开发必须遵守）

1. **内容归作者所有** — 类似文件属于文件所有者。社区(space)只是**索引**内容，不是拥有者。空间创建者不能删除/修改别人内容，只能控制展示/隐藏。
2. **模块 = 文件夹开关** — 关闭模块 = 关闭文件夹。后端 API 必须过滤 disabled module 的内容（不在 enabled_modules 列表的 module_type 不返回）。
3. **空间控制索引** — 空间可以在自己的模块中**展示/隐藏**内容（类似文件在文件夹中的索引），但不能篡改内容本身。置顶/精选/隐藏 = 索引操作。
4. **模块设置持久化到服务器** — 不能仅用 localStorage。SpaceSettings 的开关必须同步 PUT /api/spaces/{ns} 的 enabled_modules。
5. **作者可管理自己内容** — 增删改查、设置可见性（公开/私用/成员可见/密码保护）。
6. **内容可交互** — 点赞、收藏、评论、投票是所有内容的基本属性。

### 可见性层级（按从开放到封闭）

| 层级 | 可见范围 | 说明 |
|------|---------|------|
| `public` | 所有人 | 公开，类似公开网页 |
| `space_member` | 仅社区成员 | 类似群组文件 |
| `follower` | 仅关注者 | 类似好友可见 |
| `private` | 仅作者 | 类似私人文件 |

## 🔧 关键 Bug 已修复（记录防回退）
- **评论匿名Bug**: POST /api/spaces/{ns}/posts/{id}/comments 返回的 Comment 模型无 author 字段，前端显示"匿名"。修复：create_comment 返回类型改为 serde_json::Value，用 find_users_batch 查询并嵌入 author 数据（v0.2.68）
- **内容服务发帖中文路由 404**: `parse_content_path` 用 `req.uri().path()` 取到 URL 编码路径（`112233/%E6%88%91%E7%9A%84%E5%A4%A9%E6%B0%94`），未解码直接查库返回 "Not found"。修复：`parse_content_path` 入口处用 `percent_decode_str()` 先解码整个路径再解析（v0.2.58）
- **模块设置 localStorage key 迁移**: 命名空间编码变更后旧设置丢失。修复：`loadModules` 双 key 回退（先试解码 key，回退 encodeURIComponent 旧 key）（v0.2.58）
- **空间页中文路由显示 URL 编码**: `useParams()` 返回 `[...namespace]` catch-all 参数时未经 URL 解码，中文社区名（如"新的世界"）显示为 `%E6%96%B0%E7%9A%84%E4%B8%96%E7%95%8C`。修复：`namespace` 解析时对每个 segment 调用 `decodeURIComponent()`（v0.2.57）
- **中文 slug 社区 404**: 社区 slug 含中文时（如"创新"），`handle_public_path` 用 `req.uri().path()` 取到 URL 编码后的原始路径（`%E5%88%9B%E6%96%B0`），未解码就传 `get_space()` 查库失败。修复：新增 `decode_namespace()` 用 `percent-encoding crate` 解码后再查（v0.2.54）
- **Standalone 部署文件同步**: npm build 后需同步 server/ + BUILD_ID + *.json 到 standalone/.next/，否则仅首页正常其余 500（v0.2.41）
- **网关查询参数丢失**: 所有 `proxy_to_*` 函数已改用 `path_and_query()`（v0.2.7）
- **空间页面 404**: 因 git stash 导致 `[...namespace]/page.tsx` 被删，已从 git 恢复（v0.2.6）
- **Admin Axum 0.8 兼容**: 路由参数 `:id` → `{id}`（v0.2.4）
