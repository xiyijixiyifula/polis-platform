# Polis 设计哲学

> 本文档描述 Polis 平台的核心设计理念。任何开发者在修改代码前应阅读此文档。
> 原始分析: `/Users/wansichao/Downloads/社区介绍.md`

---

## 一、核心公式

> **作品是唯一实体，社区模块下的所有内容都是作品的引用（索引）。**
>
> **索引路径格式：`@社区创建者 / 社区名 / 模块名 / 作品名`**
>
> **发布入口有两个：创作者中心（独立创作）和社区模块页（场景化创作，自动关联社区/模块，可追加其他社区）。**

---

## 二、核心数据模型

### 2.1 双维度信息展示

首页 Feed 每条内容同时展示两个独立维度：

**维度一：引用路径（社区维度）**
```
@rust_writer / Rust 技术前沿 / 交流 / kankan
```
- `@rust_writer` = 社区创建者
- `Rust 技术前沿` = 社区名
- `交流` = 模块名
- `kankan` = 作品名

**维度二：创作者信息（创作者维度）**
```
原来这是一个大西瓜 · 0粉丝 · 2天前
```
- `原来这是一个大西瓜` = 作品的实际创作者
- 与社区创建者（rust_writer）**可以是不同的人**

### 2.2 路径格式

```
@社区创建者用户名 / 社区名 / 模块名 / 作品名
```

这是内容的"引用地址"——类似文件系统路径 `/home/user/documents/file.txt` 描述文件在哪里，而不是文件是谁写的。

## 三、作品与引用的关系

### 3.1 统一的作品概念

所有内容类型统称为**作品（Creation）**：
- 交流帖子 = 作品
- 知识库页面 = 作品
- 视频 = 作品
- 问答 = 作品
- 投票/问卷 = 作品
- 分享 = 作品
- 小说章节 = 作品

### 3.2 引用机制

当创作者发布时：
1. **创建作品实体**（存入 `creations` 表）—— 唯一真实数据
2. **创建引用记录**（存入 `module_refs` 表）—— 索引

社区模块页面展示的内容，是从 `module_refs` 表中查询的引用列表，每个引用指向一个真实作品。

### 3.3 Rust 类比

```
Creation   = 类型实例（堆上分配的数据）
ModuleRef  = 引用 &T（不拥有数据，只是指向数据的指针）
社区模块    = 一个容器，存放对作品的引用
```

## 四、发布入口

### 入口一：创作者中心（独立创作）

```
创作者中心 → 发布作品 → 选择模块类型 → 编写内容 → 选择投稿社区（可选）
```

从创作者视角出发——先创作作品，再决定投放到哪些社区。

### 入口二：社区模块页面（场景化创作）

```
社区页面 → 点击模块 → 点击"发布" → 跳转创作中心
→ 社区和模块已自动填写（space=namespace&module=forum）
→ 编写内容 → 可额外追加其他社区
```

从社区视角出发——在特定社区/模块场景下发起创作，默认投稿到当前社区。

**关键：可额外追加其他社区**——一次创作，多处引用。

## 五、融合模式的本质

### 传统平台的单一维度

| 产品类型 | 模型 | 创作者主权 |
|----------|------|-----------|
| 贴吧/Discord | 用户→社区→发帖，帖子属于社区 | 低 |
| B站/抖音 | 创作者→作品→推荐，作品属于自己 | 高 |

### Polis 双维度模型

```
维度一：社区视角（类似贴吧/Discord）
用户A创建社区 → 开启模块 → 用户B在社区发帖 
→ 帖子是用户B的作品被引用到用户A的社区

维度二：个人创作视角（类似B站）
用户B在创作者中心发布作品 → 作品属于用户B
→ 可引用到多个社区的不同模块
→ 个人主页展示所有作品
```

### 对各方的影响

- **社区创建者**：像吧主一样管理社区，但社区内的内容不是"属于"社区的，而是被"引用"的
- **创作者**：拥有作品所有权，一个作品可出现在多个社区，修改全局同步
- **读者**：Feed 携带完整引用路径 + 创作者信息，双向导航

## 六、与竞品的本质区别

| 平台 | 内容归属 | 跨社区/跨吧 | 创作入口 |
|------|---------|------------|---------|
| 百度贴吧 | 帖子属于贴吧 | 不支持 | 进入贴吧发帖 |
| Discord | 消息属于服务器 | 不支持 | 频道内输入 |
| B站 | 视频属于UP主 | 无社区概念 | 创作中心 |
| 微博 | 帖子属于个人 | 话题标签(弱) | 统一发微博 |
| **Polis** | **作品属于创作者，社区持有引用** | **一作品多社区引用** | **创作者中心 + 社区模块页** |

---

## 七、开发约束

基于以上设计哲学，开发中必须遵守：

1. **新增内容类型** = 新增 Creation 类型 + 对应的 ModuleRef 关联逻辑，不是新增独立表
2. **修改 Feed 展示** = 同时展示引用路径和创作者信息两个维度
3. **修改发布流程** = 保持两个入口，社区入口必须支持自动填写 + 追加其他社区
4. **删除操作** = 区分"删除引用"（从社区移除）和"删除作品"（彻底删除 Creation）
5. **API 设计** = 先创建作品再创建引用，或者从社区发布时先创建作品再自动创建引用
